# Flutter 담당 학생을 위한 기술 인수인계 가이드

> **작성 목적**: 안드로이드 사전 테스트 앱(`SmartATMPretest`)을 통해 검증된 백엔드 API 계약, 라즈베리파이 ATM QR 연동 조건, 통화 음성인식(STT) 처리 노하우 및 시연 대본을 Flutter 앱 개발 담당자에게 전달합니다.

## 1. 검증된 백엔드 API 계약

### 공통 규격
- **기본 포맷**:
  - 성공: `{"data": { ... }}`
  - 실패: `{"error": {"code": "...", "message": "..."}}` — 화면에는 `error.message`를 그대로 띄운다 (`detail`이 아니다)
- **인증 헤더**: `Authorization: Bearer <access_token>`
- **토큰 유효기간**: 12시간 (당일 아침 1회 로그인으로 종일 유지)
- **전시장 네트워크 주의**: 전시장 공유기 IP 변경에 대응할 수 있도록 **서버 URL을 앱 설정에서 동적으로 변경**할 수 있어야 합니다.

### 1-1. 로그인 (`POST /api/v1/auth/login`)
- **요청 Body**:
  ```json
  {
    "username": "halmeoni",
    "password": "<시연 비밀번호>"
  }
  ```
- **성공 응답 (200 OK)**:
  ```json
  {
    "data": {
      "access_token": "eyJhbGciOi...",
      "token_type": "bearer"
    }
  }
  ```

### 1-2. 보이스피싱 분석 (`POST /api/v1/analysis`)
- **요청 Body** (최대 2000자 제한):
  ```json
  {
    "message": "[검찰청] 귀하의 계좌가 범죄에 연루되어..."
  }
  ```
- **성공 응답 (200 OK)**:
  ```json
  {
    "data": {
      "analysis_id": 12,
      "risk_level": "DANGER",
      "risk_score": 100,
      "reasons": [
        "기관 사칭 표현 감지",
        "범죄 연루 언급 감지"
      ],
      "summary": "기관 사칭 표현 및 범죄 연루 언급 감지",
      "detected_at": "2026-09-20T05:12:33",
      "message_text": "...",
      "session_id": "VP-000012",
      "atm_action": "BLOCK"
    }
  }
  ```

## 2. QR 코드 및 라즈베리파이 ATM 카메라 인식 최적 조건

### 2-1. QR 데이터 포맷
- 라즈베리파이 ATM 카메라는 **반드시 아래 JSON 문자열 형태**만 정상 인식합니다.
  ```json
  {"session_id": "VP-000012"}
  ```
- 개인정보나 상세 분석 내용은 넣지 않습니다 (ATM이 세션 ID로 백엔드에서 직접 조회).

### 2-2. 표시 조건
- `risk_level != "SAFE"` 이고 `session_id != null` 일 때만 QR을 띄웁니다.
- `SAFE`일 때는 QR을 표출하지 않습니다.

### 2-3. 인식률 극대화 4대 수칙 (실측 권장치)
1. **화면 밝기 최대 고정**: QR 표시 화면 진입 시 기기 화면 밝기를 `1.0 (최대)`로 강제 설정하고, 화면 꺼짐 방지(`KEEP_SCREEN_ON`)를 활성화합니다.
2. **크기 비율**: 스마트폰 가로 해상도의 **70% 이상** 크기로 큼직하게 렌더링합니다.
3. **고대비 단색**: 배경은 순수 **흰색(#FFFFFF)**, QR 코드는 순수 **검은색(#000000)**으로만 표시합니다 (컬러/그라디언트 테마 금지).
4. **여백(Quiet Zone)**: QR 주변에 최소 3모듈 이상의 흰색 여백을 확보합니다.
5. **카메라 인식 거리**: 라즈베리파이 저해상도(640×480) 카메라 렌즈 기준 약 **15cm ~ 25cm** 거리가 최적 인식 범위입니다.

## 3. 통화 음성 받아쓰기(STT) 구현 노하우

### 3-1. 안드로이드 보안 정책 대응
- 안드로이드 10(API 29) 이상에서는 일반 앱의 통화 스트림 직접 녹음이 원천 차단되어 있습니다.
- **스피커폰으로 바꿔도 같은 폰에서는 받아쓸 수 없습니다.** 통화가 연결되어 있는 동안 일반 앱이
  마이크를 잡으면 안드로이드가 **무음**을 넘깁니다 (공식 문서 "Sharing audio input":
  *The call always receives audio. The app can capture audio if it is an accessibility service.*).
- 그래서 **통화 소리는 다른 기기에서 나오게 합니다.** 통화 녹음 파일이나 대본 음성을 PC·다른 폰으로
  틀고, 이 폰에서 받아쓰기를 누릅니다 (PRD 07 v1.1 이후 'B-1 녹음 재생').

### 3-2. 침묵 자동 재시작 루프 (핵심)
- 모바일 기본 `SpeechRecognizer`는 통화 중 상대방이 잠시 말을 멈추면 침묵(`onEndOfSpeech` 또는 `ERROR_SPEECH_TIMEOUT`)으로 감지하여 스스로 인식을 중단합니다.
- 사용자가 명시적으로 `[중지]`를 누르기 전까지, 침묵 또는 비치명적 에러 발생 시 **약 200~300ms 지연 후 자동으로 다시 인식을 재시작**해 주어야 통화 전체를 끊김 없이 받아쓸 수 있습니다.
- 인식된 텍스트는 이전 텍스트 뒤에 띄어쓰기로 이어 붙여야 합니다.
- **재시작은 `onResults`(결과를 받은 뒤)와 `onError`에서 합니다.** `onEndOfSpeech`는 결과가 오기
  전이라, 거기서 다시 시작하면 방금 받아쓴 문장이 버려집니다.

## 4. Flutter 대응 라이브러리 매핑

| 기능 | 안드로이드 네이티브 (사전 테스트 앱) | Flutter 권장 패키지 |
|---|---|---|
| **HTTP 통신** | Retrofit 2 + OkHttp | `http` 또는 `dio` |
| **QR 코드 생성** | ZXing (`com.google.zxing:core`) | `qr_flutter` |
| **음성 인식 (STT)** | `android.speech.SpeechRecognizer` | `speech_to_text` |
| **문자 공유 받기** | `ACTION_SEND` Intent Filter | `receive_sharing_intent` |
| **화면 켜짐 유지** | `FLAG_KEEP_SCREEN_ON` | `wakelock_plus` |
| **화면 밝기 제어** | `WindowManager.LayoutParams` | `screen_brightness` |

## 6. 실제 서버·ATM에 맞물려 확인한 규칙 (2026-10-18)

안드로이드 사전 테스트 앱의 코드를 그대로 컴파일해 백엔드와 라즈베리파이 ATM 코드에 연결해 본 결과입니다.
Flutter로 옮길 때 **같은 실수를 되풀이하지 않도록** 남깁니다.

| 규칙 | 지키지 않으면 (실측) |
|---|---|
| **QR은 서버가 돌려준 `session_id`로만 만든다.** 서버에 못 닿았거나 로그인이 안 됐으면 결과는 '서버 확인 전 · 참고용'으로만 보여 주고 QR은 만들지 않는다 | 앱이 지어낸 `local-…` QR을 ATM은 "등록되지 않은 QR"로 보고 **막지 않는다** — "처음으로" 한 번에 출금됨 |
| **401이면 다시 로그인하게 한다.** 저장된 토큰을 지우고 `error.message`를 띄운다 | 토큰 12시간 — 전시 이틀째에 조용히 위 경우로 넘어감 |
| **앱에 규칙 엔진을 둔다면 서버(`backend/analysis/keywords.py`)와 똑같이** — 7개 범주, 범주당 한 번 가산, 0~29/30~69/70~100 | 다른 규칙을 썼더니 98문장 중 33문장의 등급이 서버와 달랐다 |
| **통화 중 문장마다 `POST /api/v1/analysis`를 보내지 않는다.** 통화 중 경고는 앱 규칙으로, 서버에는 통화 종료 후 한 번 | 요청마다 세션이 생겨 콜센터 목록에 같은 통화가 5줄 |
| **시연 문자는 서버 규칙으로 먼저 돌려 본다.** 새 문자를 넣으면 `tools/make_judgement_cases.py`로 서버 판정을 확인한다. 링크만 있고 돈을 요구하지 않는 스미싱은 7개 범주 밖이라 SAFE다 (팀 결정, 2026-10-19) | 사기 시연 문자 5개 중 3개가 서버에서 SAFE라 QR이 안 나왔다 — 서버 키워드 보강(상품권·핀번호·선입금 등)과 #5 교체로 해결 |
| 빈 텍스트 오류(`MESSAGE_REQUIRED`)는 **422**다 | — |
| QR 내용은 영문·숫자뿐이라 UTF-8/ECI 지정이 필요 없다 | ZXing에 UTF-8을 지정하면 ECI가 붙어 OpenCV가 읽을 때마다 경고를 찍는다 (해독은 됨) |
